The loop

Behaviour in, a case out

01BrowseViews, searches, dwell. Batched and non-blocking.
02Threshold12 meaningful events, or a real shift in interest.
03ReasonInfer what this person is actually solving.
04RetrieveHybrid search over the real catalog.
05GradeIs each candidate actually supported?
06ArgueA case citing the user's own actions.

It ends in buy this one. Hardy never says don't buy. It redirects you to the thing worth buying.

The agent

A graph, not a prompt chain

GroundedRetrieval is hard-filtered to the catalog. Generation cannot invent a product.

Efficiency, an explicitly judged axis

Be smart about when you call the model

Fires when 12 meaningful events since the last recommendation, the top category shifting, the 08:00 IST digest, or an admin asking
Suppressed when Fewer than 5 events, one ran in the last 10 minutes, the profile hash is unchanged, which is the cache hit
Model calls per event0.700Live on /debug, computed from the same tables the storefront uses.
Cache key covers4Categories, products, queries, catalog version. An edit invalidates it.
Digest over stale behaviour0LLM calls. There is a test asserting it.
Dual-write

Two stores that cannot drift

On writeCreate, edit and delete each write SQLite and Qdrant together. If the embedding fails, neither is kept.
Proof, not a claimGET /api/admin/consistency counts both stores and names anything missing or orphaned.

The bet

Same skeleton, opposite instinct

Every other entry builds an agent that persuades you to buy more. Hardy uses the identical mandated architecture: behavioural tracking, dual write to SQL and a vector database, agentic retrieval, persuasive generated copy, every call through Mesh. It points that at the buyer instead of the seller.

NotAn affiliate site. No commissions, no sponsored placement.
NotAnti-consumption. It never says don't buy.
NotA review site. Ownership, serviceability, cost per year, not stars.
